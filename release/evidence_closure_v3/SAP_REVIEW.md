A title or TOC membership alone proves no substantive claim; a query parameter alone proves no version served. 2. Reviewer must be an independent SAP domain reviewer, not the answer generator/label author. Record identity, role/qualification, independence/conflicts, date/signature and source access provenance. For the first pass provide only question/source access and [blank worksheet](sap-review-worksheet.csv), **withhold model answers, frozen AI gold, expected behavior and matcher flags**. The reviewer independently determines answerability, applicable version, required facts/list membership/procedure scope and sufficient evidence before seeing candidates.
3. Then disclose immutable candidate answers, raw cited context and [focus pointers](sap-focus-evidence.json), retaining the initial signed blind determination. For each factual claim record answer span → exact authoritative source span → guide/page/version/build/locale, completeness/scope/polarity/relationship, entailment versus navigation-only, and final rationale. Add rows for each claim/source; a single case row is not a limit on claim-level review. Never fill null URL/version/source fields by guessing.
4. Second independent reviewer adjudicates conflicts, high-risk identity/version and prohibited-claim cases. Unknown/conflicting/insufficient authority stays UNVERIFIED; runtime remains fail-closed, not an invented mapping. Any accepted new gold is a **separately named/versioned signed artifact** with rationale, sources/hashes and approval, not a modification of the frozen labels or a runtime activation. Source/corpus/store changes require a separate explicitly approved task, not this package.
5. Rerun full current evidence after real resources exist and review every answer, abstention, negative and ambiguity. Report frozen metrics unchanged alongside separately adjudicated substantive results/drift. Do not remove difficult/rejected/incorrect cases or let abstention count as substantive positive correctness.
