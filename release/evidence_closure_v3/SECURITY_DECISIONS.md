## Safe evidence plan for security authority

1. **Inventory actual deployment without triggering configuration constructors.** Obtain owner-approved OS/container/image/interpreter/package/native/model/store SBOMs and signed config/routes/provider graph, process ownership/listeners, inbound/outbound ACLs, service identities, mounts, secrets/log policy and SDK consumers. Inspect approved source/static config and offline byte inventories, not untrusted SDK properties. Current scripts' explicit vectors/no observed HttpClient use narrow a path but do not prove target non-exposure or absence of other consumers.
2. **Contain before running.** Private host/network only; no public previews/ingress; no Chroma HTTP listener reachable by untrusted callers; deny unapproved egress; non-admin service identity; disjoint private storage/model roots; approved synthetic fixtures. Gateway must not pass raw Chroma/config/admin endpoints or arbitrary tenant/database headers to a shared trusted backend. Product debug denied and secrets not browser-accessible.
3. **Prove authorization/isolation, not only login.** Test anonymous, principal A, principal B and privileged role separately; own vs other tenant/database/collection/document, guessed/swapped IDs and defaults. Cover list/get/query/create/get-or-create/update/delete/upsert/add/count/config/tenant/database administration where applicable, all v1/v2 routes, aliases/encoding and direct/internal SDK access. Expected decision/status and zero resource/metadata/embedding/document leakage must be asserted; unauthenticated and cross-resource mutation forbidden. A missing route is evidence only if every bypass is denied and intended own operations succeed.
4. **Safe constructor verification only.** If approved, use separately owned synthetic configurations with an inert marker constructor/call counter and explicit vectors to establish call ordering. No shell/code-execution payload, no production/provider poisoning, no paid provider/network. Preserve traceback/counters/actual source hashes and demonstrate both create and update/local SDK boundaries. Do not rerun the old closure-v1 inert probe in-place: it writes an adjacent historical JSON. A new probe requires approved separate output/fixture scope; it is not executed here.
5. **Close only with evidence.** If a future patched dependency is chosen, owner must establish a released fixed artifact/range and test supported Python/OS/native/store/cleanup/vector/golden/current-RAG/full-backend/browser compatibility before adoption. No version-only upgrade or unmerged PR adoption here. If containment is proposed instead, retain precise residual conditions, bypass tests, monitoring/revocation and human approval; policy may still prohibit readiness for a material reachable high/critical issue.
